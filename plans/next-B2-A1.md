## B2 — UDP/JSON 보안 하드닝 라이브러리 (메인)

### 한 줄
2023 발견 → RoboSec 확증 → B2 방어 구현으로 **한 서사가 닫힌다.**

- 2023 5G/UDP 인턴: 오류주입 시험표에서 **CRC32·시퀀스·발신자 ID 전부 미검사** 확인.
- RoboSec(2026-08-30 실기): **F2 = 스푸핑·재전송이 실제 FSM 전이와 속도 구동을 일으킴** 확증.
- B2: 그 결함을 닫는 **재사용 가능한 프레이밍/검증 계층 + 퍼즈 하네스**.

### 설계에서 정직하게 갈라야 할 지점 (중요)
"길이+CRC32+시퀀스+버전"만으로는 **F2(스푸핑)를 못 막는다.** 결함마다 맞는 계층이 다르다:

| 확증된 결함 | 공격(attacker.py) | 맞는 방어 | 오해 금지 |
|---|---|---|---|
| 손상 패킷 | a1-corruption | 길이 + 버전 + CRC32 | CRC는 무결성이지 인증이 아니다 |
| 재전송 | a3-replay | 단조 증가 시퀀스 + 수신 윈도우 | — |
| 극단 수치 | a4-extreme | 값 검증/클램프(도메인) | 프레이밍 계층 밖 |
| **스푸핑(F2)** | a2-spoof | **HMAC(사전공유키)** | ⚠️ CRC32로는 절대 못 막음 — 공격자가 CRC 재계산 |

grippers 는 폐쇄 LAN 이므로 **사전공유키 HMAC** 가 스푸핑의 정직한 해법이다.
이 구분을 문서에 명시하는 것 자체가 보안 이해도의 증거가 된다.

### 단계 (파트타임)
- **W1 — 코덱 + property 테스트.** 와이어 포맷 확정(ver·len·seq·payload·crc·mac).
  Python 코덱 구현 + property-based 테스트. **RoboSec `attacker.py`(a1~a5)를 오라클로**
  물려 a2/a3 가 거부되는 것을 보인다.
- **W2 — 퍼즈 + 통합.** Atheris 퍼즈 하네스로 파서를 두들겨 발견 수정.
  grippers 도메인에 어댑터(Ports & Adapters)로 끼워 **녹화 bag 재생으로 F2 before/after** 확증
  (같은 a2/a3 주입이 방어 전 = FSM 이동, 방어 후 = 거부).
- **W3 (스트레치 · 로드맵 융합).** 디코더를 C 로 재구현해 **libFuzzer/AFL++ 타깃**으로.
  포트폴리오가 "실제로 쓴 뒤에 올린다"고 못 박은 fuzzing 도구를 처음 쓰는 자리.
  (udp-network-lab 이 로드맵상 2026-11 예정 — B2 가 그 조기 착수분이 된다.)

### 산출물
- 독립 repo `udp-network-lab`(github/ 초안 존재) 또는 `secure-framing`.
- before/after 리포트: RoboSec a2/a3 가 성공하던 것이 방어 후 거부됨.
- (W3 시) libFuzzer/AFL++ 크래시·커버리지 결과.

### 한계로 미리 적을 것
- HMAC 사전공유키 배포·회전은 범위 밖(폐쇄 LAN 가정 명시).
- 실기 재검증은 녹화 bag 재생으로 대체(9/8 이후 하드웨어 없음).

## A1 — OpenVINO 엣지 최적화 (병렬 사이드)

### 병렬이 성립하는 이유
A1 은 데스크탑 Arc GPU 에서 **돌려놓고 기다리는** 벤치 작업이라,
맥에서 B2 를 짜는 동안 컴퓨트가 겹치지 않는다.

### 범위
- best.pt → ONNX → OpenVINO IR(FP16) → **NNCF PTQ INT8**(캘리브레이션 = 녹화/합성 프레임).
- 벤치 대상 5종: PyTorch(CPU) · OVIR-FP16(Arc GPU) · OVIR-INT8(Arc GPU) ·
  OVIR-INT8(맥 arm64 CPU) · Hailo-INT8(기존 76.5 FPS 인용).
- 지표: 지연(mean/p95) · 처리량 · **정확도 델타**.

### 정직한 축 = 정확도
지연만 재면 반쪽이다. **INT8 양자화 후 인지 게이트(CONF 0.70 + MIN_BOTTOM_Y)가
살아남는지**를 210초 녹화로 재측정 — "게이트 통과율 유지 여부"가 진짜 질문.

### 산출물
- 벤치 표 + 짧은 리포트. grippers-perception 문서 확장 또는 별도 `edge-optimization` 조각.
- 기간 1~2주, 대부분 실행 시간.

### 한계로 미리 적을 것
- mAP 정답 라벨이 없으면 정확도는 게이트 통과율/검출수로 대리 측정(그 점 명시).
