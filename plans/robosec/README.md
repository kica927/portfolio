## 왜 이 프로젝트인가

기존 fuzzer 는 **crash 를 찾습니다.** 로봇 제어 소프트웨어에서 crash 는 오히려
안전한 실패입니다 — 프로세스가 죽으면 명령이 끊기고 워치독이 돕니다.

정말 위험한 것은 **crash 없이 계속 도는 상태**입니다. 파지 중인데 바퀴가
돌거나, STOP 을 받았는데 속도가 남아 있거나, 낡은 명령이 새 명령처럼 실행되는
것. 프로세스는 멀쩡하고 로그도 깨끗한데 로봇이 잘못 움직입니다.

**RoboSec 는 crash 가 아니라 물리·상태 안전 불변식의 위반을 찾습니다.**

## 대상 시스템

제가 직접 만든 실제 시스템입니다 — 문헌의 예제가 아닙니다.

- [`kica927/grippers`](https://github.com/kica927/grippers) — Raspberry Pi 5 ·
  ROS 2 Humble · 메카넘 베이스 + SO-ARM101 · 미션 FSM 7상태
- [`kica927/grippers-host-mac`](https://github.com/kica927/grippers-host-mac) —
  Host PC (오버헤드 인식 · 경로 계획 · 명령 권한)

시스템을 만든 사람이 그 시스템의 위협 모델을 쓴다는 것이 이 프로젝트의 전제
입니다. **어디에 방어층이 있고 왜 거기 있는지 알고 시작합니다.**

### 방법론 — 모델 기반 탐색 + 제한된 물리 검증

**로봇 하드웨어 접근은 2026-09-08 에 종료됐습니다.** 그래서 실험은 실기 주입이
아니라 다음 구성으로 갑니다.

| | |
|---|---|
| **SUT** | 하드웨어 비의존 도메인 계층 — `motion.py` · `baseline_mission.py` · `udp_host_link.py` (순수 파이썬, ROS·하드웨어 미의존) |
| **정답지** | 하드웨어 종료 전 녹화한 `ros2 bag` 실기 궤적 |
| **물리 상수** | 종료 전 실측한 정지 지연 · 워치독 발동 시간 · 이동 거리 |
| **검증 순서** | ① 모델이 녹화 궤적을 재현하는지 수치로 보임 → ② 그 위에서 탐색 |

이것은 사이버-물리 시스템 보안 연구의 표준 구성입니다. 중요한 것은 **모델이
실측과 얼마나 맞는지 보이는 것**과 **검증하지 못한 것을 정확히 밝히는 것**입니다.

> 도메인 계층이 하드웨어를 모르게 설계돼 있어서 이것이 가능합니다 —
> grippers 를 Ports & Adapters 로 만들고 Fake 어댑터를 갖춘 것의 배당금입니다.

## 진행 상황

- **2026-08-30 — in-process 하네스 완성.** grippers 도메인 계층을 하드웨어 없이
  구동해 A1·A2·A4·A5·A6 을 실제 코드에 대해 검증했습니다. **20/21**, 그리고
  결함 하나(F1: NaN 속도가 클램프를 통과)를 발견했습니다. 근거는
  [`threat_model.md` §7](threat_model.md).
- **2026-08-30 — 실기 확증 완료.** 같은 날 실제 차량(바퀴를 받침대에 올려 띄운 채)에
  다섯 공격을 주입하고 베이스 출력 `/cmd_vel` 과 `/mission/state` 를 녹화해 모델과
  대조했습니다. **모델이 실물과 일치합니다.** in-process 가 예측한 두 구멍(**F1 NaN
  누출 · F2 상태와 무관한 속도 실행**)이 실제 `/cmd_vel` 에 그대로 나타났고(nan 1
  프레임, 속도 0.1 누출), FSM 은 전 과정 IDLE 을 유지했으며, 방어 넷(클램프 ·
  회전순수성 · 상태게이팅 · 손상폐기)은 실물에서도 유지됐습니다. 불변식 스캐너는
  4440 레코드 중 위반 1건(그 nan)만 보고 — 예측과 정확히 일치합니다.
- **관측 — 하류 방어 심층.** 샌 NaN · 속도가 `/cmd_vel` 까지는 갔으나 **바퀴는 한
  번도 돌지 않았습니다**: 그 아래 기구학(`odom_publisher`)/STM32 계층이 NaN · 미세
  속도를 실제 구동으로 옮기지 않았습니다. 도메인엔 구멍이 있으나 실물 로봇은 한 겹
  더 막혀 있다는 뜻입니다. 단 이는 **우연한 보호이지 설계된 방어가 아니므로** F1 ·
  F2 는 여전히 도메인에서 고쳐야 합니다(F1: NaN/Inf→유한값 치환, F2: 속도 경로에
  상태 게이트).

## 윤리 · 범위

**대상은 제가 만든 캡스톤 로봇의 소프트웨어이고, 실험은 제 노트북에서만
수행합니다.** 하드웨어 실험은 2026-09-08 이전에 격리된 실험망에서 수행했습니다.
타인의 로봇이나 공개 배포된 ROS 2 시스템을 대상으로 하지 않습니다.

발견된 문제는 먼저 `grippers` 저장소에 수정으로 반영하고, 그 뒤에 결과를 씁니다.
