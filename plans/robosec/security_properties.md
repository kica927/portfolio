# RoboSec — 안전/보안 불변식

**무엇을 "위반"으로 셀 것인가를 실험 전에 못 박아 둡니다.** 실험을 돌린 뒤에
기준을 정하면 결과에 맞춰 기준이 움직입니다.

각 불변식은 **관측 가능**해야 합니다 — 코드를 읽어서가 아니라 로그·토픽·측정으로
위반을 판정할 수 있어야 합니다.

---

## 형식

```
I<n>  이름
  진술    : 언제나 참이어야 하는 것
  근거    : 왜 이것이 안전 속성인가
  관측    : 어떻게 위반을 감지하는가
  심각도  : 위반 시 물리적 결과
```

---

## I1 — 파지 중 베이스 정지

```
진술    FSM 상태 ∈ {GRASP} 인 동안 |linear_x| = |linear_y| = |angular_z| = 0
        (단, GRASP 미세 전진 구간은 명시적 예외로 별도 계수)
근거    팔이 바닥 자세로 내려와 있는 상태에서 베이스가 움직이면 관절에
        측면 하중이 걸리고, 물체가 턱 밖으로 밀려난다
관측    /cmd_vel 과 /mission/state 를 동시 기록 후 시간 정렬
심각도  🔴 높음 — 서보 손상 가능
```

> **예외를 명시하는 것이 중요합니다.** 이 시스템의 파지는 팔이 열린 채 내려와
> 있고 **차체가 전진해 물체를 턱 사이로 밀어 넣습니다.** 그러니 GRASP 중의 전진은
> 위반이 아니라 정상 동작입니다. 위반은 **계산된 미세 전진량(관측 − 클래스별
> 턱선)을 넘는 이동**입니다.

## I2 — STOP 은 모든 속도를 0으로 만든다

```
진술    stop=true 명령 수신 후 T_stop 이내에 모든 명령 속도 = 0
근거    정지가 지연되면 그동안의 이동이 그대로 오버슈트다
관측    stop 수신 시각 ~ 마지막 비영 /cmd_vel 시각의 간격
        T_stop 은 실측으로 정한다 (현재 추정 235 ms — Host 125 + UDP 10 + Pi 100)
심각도  🔴 높음
```

**측정하지 않은 T_stop 을 임의로 채우지 않습니다.** E4 실험의 산출물입니다.

---

## I3 — 유효하지 않은 상태에서 액추에이터 명령이 나가지 않는다

```
진술    수신 명령의 state 가 FSM 의 현재 상태에서 수용 가능한 어휘가 아니면
        어떤 액추에이터 명령도 발행되지 않는다
근거    상태 게이팅(D4)이 실제로 닫혀 있는지가 replay 방어의 전부다
관측    거부 로그와 /cmd_vel · 팔 서비스 호출의 부재를 함께 확인
심각도  🔴 높음
```

---

## I4 — 낡은 명령은 거부되거나 안전하게 처리된다

```
진술    링크 침묵이 HOST_COMMAND_TIMEOUT_CYCLES(3) 을 넘으면 링크 끊김으로
        판정되고 안전 동작으로 전이한다
근거    워치독(D3)이 설계대로 도는지. 제어 주기가 1.6 Hz 였을 때
        "3사이클"은 0.3초가 아니라 1.8초였다 — 같은 코드가 6배 느슨해졌다
관측    마지막 명령 수신 시각 ~ 안전 전이 시각
심각도  🟠 중간 — 단, 주기 저하와 겹치면 높음
```

> **이 불변식은 이미 한 번 실제로 깨졌습니다.** 워치독 코드는 옳았는데 제어
> 주기가 느려지면서 실효 타임아웃이 6배가 됐습니다. **시간이 사이클로 표현된
> 상수는 주기에 대한 숨은 의존성을 갖습니다.**

## I5 — 속도 크기가 물리 한계를 넘지 않는다

```
진술    |linear| ≤ AGREED_LINEAR_MPS (0.1)
        |angular| ≤ AGREED_ROTATION_RAD_S (0.25)
        바구니 접근 구간에서는 |linear| ≤ 0.06
근거    속도 클램프(D1)가 Host 손상·스푸핑 뒤에도 남는 마지막 층이다
관측    /cmd_vel 값을 직접 검사 — 가장 쉽게 자동화되는 불변식
심각도  🔴 높음
```

## I6 — 제자리회전은 정말 제자리다

```
진술    angular_z ≠ 0 이고 (linear_x ≠ 0 또는 linear_y ≠ 0) 인 명령은
        실행되지 않고 Host 에 거부로 반환된다
근거    팀이 합의한 명령 어휘는 직진·수평이동·제자리회전·제자리정지 넷이다.
        회전에 병진이 섞이면 그 넷 중 무엇도 아니다 — 추측해서 하나를
        고르는 대신 거부한다
관측    해당 명령 주입 후 거부 반환의 존재와 /cmd_vel 의 부재
심각도  🟠 중간
```

---

## I7 — 명령을 보냈으면 실제로 움직인다 (생존성)

```
진술    비영 속도 명령이 지속되는 동안 오도메트리 변위가 감지된다
근거    D7. 데드밴드(0.05) 아래 속도는 아무리 오래 줘도 안 움직이는데
        /odom_raw 는 움직였다고 보고한다 — 조용한 실패다
        실측: 62초간 전진 명령, 실제 이동 0.1 mm (모터 전원 문제)
관측    명령 적분값과 오도메트리 변위의 괴리
심각도  🟠 중간 — 안전 위반은 아니지만 미션 실패이고 진단이 어렵다
```

---

## I8 — 서비스 실패 보고가 사실이어야 한다

```
진술    상위 FSM 이 보고하는 실패 사유는 실제로 일어난 일과 일치한다
근거    실측에서 팔은 정상 동작했는데 호출자의 타임아웃(3.0s < 서버 상한 5.5s)
        때문에 "servo 1이 거부했다" 는 사유가 올라왔다.
        거짓 실패 보고는 그 자체로 안전 문제다 — 잘못된 복구 경로를 탄다
관측    상위 보고와 하위 서비스 로그의 대조
심각도  🟠 중간
```

## 위반 계수 규칙

| 구분 | 셀 것 | 세지 않을 것 |
|---|---|---|
| **위반 1건** | 하나의 불변식이 하나의 실행에서 깨진 것 | 같은 원인의 반복 발생 (원인 단위로 1건) |
| **crash** | 프로세스 종료 · 예외 미처리 | 의도된 거부 · fail-fast 종료 |
| **재현 가능** | 최소화된 입력으로 3/3 재현 | 1회성 관찰 (별도로 "미확정" 으로 기록) |

---

## 측정 지표

측정되지 않은 숫자는 절대 예상으로 채우지 않습니다.

- 생성 입력 수
- 상태 전이 커버리지 (FSM 7상태 × 전이)
- 고유 실패 수
- **불변식 위반 수 (I1~I8 각각)**
- 최초 위반까지의 시간
- crash 수 (참고 지표 — 주 지표가 아님)
