# RoboSec — Threat Model

**대상**: `grippers` — Host PC ↔ Raspberry Pi 5 로 나뉜 ROS 2 모바일 매니퓰레이터
**작성**: 2026-08-29 (초안) · 시스템 실측 기준
**범위**: Host↔Pi 명령 링크와 Pi 측 미션 FSM. 인식 모델 자체(적대적 예제)는
이 문서의 범위 밖입니다.

---

## 1. 시스템 경계

```
        ┌─────────────────────────────────────┐
        │  Host PC (macOS)                    │   신뢰 도메인 A
        │  좌표 · 경로 · 명령 권한             │
        └──────────────────┬──────────────────┘
                           │
   ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ┼ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─   ← 신뢰 경계 1
       UDP/JSON  5005 명령 │ 5006 보고               (공유 LAN / WiFi)
   ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ┼ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─
                           │
        ┌──────────────────┴──────────────────┐
        │  Raspberry Pi 5                     │   신뢰 도메인 B
        │  미션 FSM · 속도 클램프 · 워치독     │
        └──────────────────┬──────────────────┘

       ROS 2 / DDS  (ROS_DOMAIN_ID=21, SROS2 미적용)
   ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ┼ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─
                           │
              ┌────────────┴────────────┐
              │                         │
         base_driver               arm_driver
         (바퀴 · LiDAR)          (서보 6축 · 그리퍼)
              │                         │
   ─ ─ ─ ─ ─ ─┼ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ┼ ─ ─ ─ ─ ─   ← 신뢰 경계 3
```

**경계 3 이 이 시스템을 일반 소프트웨어와 다르게 만듭니다.** 경계 1·2 를 넘은
잘못된 값은 재시작으로 되돌릴 수 있지만, 경계 3 을 넘으면 물체가 부서지거나
로봇이 가구에 부딪칩니다.

## 3. 관측된 공격면 — 코드에서 확인한 사실

아래는 추정이 아니라 **`domain/adapters/real/udp_host_link.py` 를 읽고 확인한
현재 구현의 성질**입니다.

### 3-1. 명령 소켓은 모든 인터페이스에 열려 있고 송신자를 검사하지 않는다

```python
self._rx.bind(("0.0.0.0", command_port))     # 5005
...
payload, _addr = self._rx.recvfrom(RECV_BUFFER)   # ← _addr 를 버린다
```

같은 망의 임의 호스트가 보낸 UDP 데이터그램이 Host 의 것과 **구별되지 않습니다.**

### 3-2. 인증 · 무결성 검사가 없다

페이로드는 평문 JSON 입니다. MAC 도, 서명도, 공유 비밀도 없습니다.
`_parse()` 는 **문법**만 검사합니다 — JSON 으로 안 읽히면 버리지만, JSON 으로
읽히기만 하면 출처를 묻지 않습니다.

### 3-3. 시퀀스 번호도 타임스탬프도 없다

프로토콜 필드는 다섯 개입니다: `state · linear_x · linear_y · angular_z · stop`.
**신선도를 판단할 수단이 페이로드 안에 없습니다.** 수신 시각으로만 최신을
가릅니다.

### 3-4. 마지막 것이 이긴다

수신 스레드는 큐를 쌓지 않고 최신 명령만 덮어씁니다.

```python
with self._lock:
    self._latest = command
    self._fresh = True
```

이것은 **의도된 설계**입니다 — 실어 나르는 것이 "그 순간의 속도 명령"이라
오래된 패킷은 쓸모가 없기 때문입니다. 다만 보안 관점에서는, 공격자가 정상
명령보다 조금만 자주 보내면 **정상 명령이 읽히기 전에 항상 덮인다**는 뜻이기도
합니다.

### 3-5. DDS 계층에 접근 제어가 없다

`ROS_DOMAIN_ID=21` 은 팀 합의값이지 보안 경계가 아닙니다. SROS2 (DDS-Security)
를 적용하지 않았으므로, 같은 망에서 같은 도메인 ID 를 쓰는 노드는 `/cmd_vel` 에
직접 발행할 수 있습니다. **경계 1 을 우회해 경계 2 로 바로 들어가는 경로**입니다.

## 4. 이미 존재하는 방어층

공격면만 나열하면 실제보다 나쁘게 보입니다. **Pi 쪽에 의도적으로 넣어 둔
방어층이 여럿 있고, RoboSec 의 목적은 그 층들이 어디까지 버티는지 재는
것입니다.**

| # | 방어층 | 구현 위치 | 막는 것 |
|---|---|---|---|
| D1 | **속도 클램프** | `domain/task/motion.py` | 크기가 과도한 속도. 방향은 보존하고 크기만 합의값(0.1 m/s · 0.25 rad/s)으로 제한 |
| D2 | **제자리회전 순수성 검사** | `motion.py` | 회전에 병진이 섞인 명령을 **거부하고 Host 에 되돌림** ("모르면 실패") |
| D3 | **링크 워치독** | `baseline_mission.LinkWatchdog` | 연속 결측 3사이클 → 링크 끊김으로 판정 |
| D4 | **상태별 명령 게이팅** | 미션 FSM | IDLE 은 GRASP 명령을 받지 않는 식으로 상태가 수용 어휘를 제한 |
| D5 | **손상 패킷 폐기** | `UdpHostLink._parse()` | 반쯤 읽어 0으로 채우지 않음 — 그 0은 "정지"가 아니라 "모른다" |
| D6 | **`None ≠ 정지`** | `latest_command()` | 링크 끊김과 정지 지시를 서로 다른 사건으로 유지 |
| D7 | **구동계 생존 래치** | `baseline_mission` | 명령을 보냈는데 오도메트리가 안 움직이면 알아챔 |
| D8 | **관절 절대 한계** | 팔 서비스 | 상대 회전의 누적을 교시 정면 기준 절대각으로 차단 |

> **D1 의 배치가 설계상 중요합니다.** 속도 한계는 그것을 어길 수 있는 쪽(Host)이
> 아니라 **물리적으로 집행할 수 있는 쪽(Pi)** 에 있습니다. Host 가 손상되거나
> 스푸핑되어도 이 층은 남습니다.

얕아집니다.

## 6. 1차 실험 (A1~A3) — 무엇을 물을 것인가

**하나의 명확한 질문부터 시작합니다. 처음부터 모든 공격을 구현하지 않습니다.**

| 실험 | 질문 | 예상 방어층 | 관찰할 것 |
|---|---|---|---|
| E1 | 손상 페이로드를 초당 N개 주입하면? | D5 | 정상 명령의 실효 수신율, 경고 로그 폭증 여부 |
| E2 | 유효 형식의 속도 명령을 정상보다 자주 주입하면? | D1 (크기만) | **D1 은 크기만 자르고 방향은 보존한다** — 공격자가 방향을 지정할 수 있는가 |
| E3 | 이전 GRASP 명령을 나중에 재전송하면? | D4 | 상태 게이팅이 replay 를 실제로 막는가. FSM 이 그 상태로 돌아왔을 때는? |
| E4 | 링크를 완전히 침묵시키면? | D3, D6 | 워치독 발동까지 걸린 실제 시간, 그동안의 이동 거리 |

**E2 와 E3 가 핵심입니다.** D1 은 *크기* 만 제한하므로 합의 속도 안의 명령은
전부 통과합니다. D4 는 상태에 의존하므로, FSM 이 어차피 그 상태에 있을 때는
replay 를 구별할 수단이 없습니다 — 시퀀스 번호가 없기 때문입니다.

## 7. In-process 실측 (2026-08-30, 하드웨어 이전)

grippers 는 Ports & Adapters 라 도메인 계층이 하드웨어 없이 Fake 어댑터로
끝까지 돕니다. 그래서 A1·A2·A4·A5·A6 을 **지금 실제 코드에 대해 실행**해
확정했습니다 — 6장의 "예상"이 아니라 측정입니다. 실행 코드와 원자료는 별도
하네스(`~/Desktop/intel/robosec`, 비공개)에 있고, 여기에는 결과만 옮깁니다.

**전체 20/21.** 유일한 미통과가 실제 발견입니다.

### 방어가 성립한 것

| 공격 | 방어 | 결과 |
|---|---|---|
| A1 손상 패킷 6종 | D5 폐기 | ✅ 전부 `None` — 정지로도 오독되지 않음 |
| A4 극단 수치 (±1000·inf) | D1 클램프 | ✅ 크기만 잘리고 방향 보존 |
| A2 회전+병진 혼합 | D2 거부 | ✅ 거부 + 정지 + 사유 |
| A5 IDLE→GRASP 전이 | D4 게이팅 | ✅ 전이 차단 |
| A6 명령 없음(None) | D6 | ✅ 스스로 정지를 만들지 않음 |

가설이 맞은 부분: **D1 은 크기만 자르고 방향은 보존**하며(공격자가 방향을
지정할 수 있음), **D4 는 전이만 막고 시퀀스 번호가 없어 replay 를 구별 못 함**.

### F1 🔴 — NaN 속도가 D5·D1 을 모두 통과한다

가설에 없던 발견입니다. `{"linear_x": NaN}` 은 유효한 JSON float 라
`_parse`(D5)가 안 버리고, `_clamp` 의 `min(abs(nan), limit)` 이 nan 이라
D1 도 못 막습니다. 결과적으로 `base.apply_velocity(nan, …)` 까지 도달합니다
— probe 세 개로 각 단계를 확인했습니다.

극단값 중 **nan 만** 샙니다(inf 는 클램프됨). 완화책은 파싱 경계에서
`math.isfinite()` 로 거르는 것이며, 이는 D5 의 "계약 위반은 버린다" 관례와
일치합니다. **수정은 grippers 팀 판단이고, 이 프로젝트는 결함을 보이는
데까지가 역할입니다.**

### F2 🟡 — 상태 게이팅은 전이만 막고 속도는 막지 않는다

IDLE 에서 GRASP 명령을 보내면 전이는 차단되지만, 그 명령에 실린 속도는
`_drive` 로 그대로 실행됩니다(IDLE 에서 `apply_velocity` 관측). 명령 소켓이
인증되지 않는다는 사실(3-1)과 합치면, **공격자가 IDLE 로봇을 임의 속도로
움직일 수 있다**는 뜻입니다. 코드 버그가 아니라 경계 설계 질문이라, 9월 8일
실기에서 "IDLE 로봇에 속도만 주면 바퀴가 실제로 도는가"로 확증합니다.

### 완화책 (변함없음)

세 결과 모두 같은 곳을 가리킵니다 — **단조 증가 시퀀스 번호 + 공유 비밀 MAC +
파싱 단계 유한성 검사.** 필드 두 개와 검사 한 줄로 A2·A3 과 F1 이 함께 닫힙니다.

### 하드웨어로 확증할 것 (9월 8일)

| 항목 | 왜 실기가 필요한가 |
|---|---|
| F1 을 실제 베이스에 | nan 속도를 받은 STM32 가 정지/유지/폭주 중 무엇을 하는가 |
| F2 를 실제 차량에 | IDLE 상태 속도 주입 시 바퀴가 실제로 도는가 |
| A3 를 실제 무선에 | replay 가 실기 타이밍에서 상태를 흔드는가 |

## 8. 이 문서의 한계

- Host 측 코드는 다른 팀원이 유지하는 부분이 있어, 이 문서의 사실 확인은 **Pi
  측 구현**에 대해서만 완전합니다.
- `stop` 필드의 처리 경로는 아직 코드 대조를 하지 않았습니다.
- 실제 시연 환경의 망 구성(전용 라우터 / 시연장 공용 WiFi)이 확정되지 않아,
  "같은 망의 임의 호스트"가 현실적으로 누구인지가 아직 열려 있습니다.
