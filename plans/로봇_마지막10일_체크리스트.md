# P1 — 녹화 (가장 중요하고 가장 쌉니다)

팀 README 에 이미 적혀 있는 원칙입니다.

> **"실기 시행은 되돌릴 수 없고, 로봇 1대를 5명이 나눠 쓰므로 녹화가 곧 시간"**

**이제 그 말이 문자 그대로 참이 됩니다.** 9월 8일 이후 RoboSec 의 실험 대부분은
녹화본 위에서만 가능합니다. 오늘부터 로봇을 켤 때마다 녹화를 겁니다.

## 기본 명령

컨테이너 안에서, 셸을 열자마자:

```
export ROS_DOMAIN_ID=21
source /opt/ros/humble/setup.bash
source /ros2_ws/install/setup.bash
mkdir -p /grippers/recordings/final
cd /grippers/recordings/final
```

**영상 토픽을 뺀 전체 녹화** — 이게 기본입니다. 영상은 용량을 순식간에 먹는데
RoboSec 에는 거의 안 쓰입니다.

```
ros2 bag record -a -x ".*(image_raw|image_color|compressed|points).*" \
  --max-bag-size 2000000000 -o run_$(date +%Y%m%d_%H%M%S)
```

## 반드시 녹화가 걸린 채로 돌려야 하는 것

| # | 시행 | 왜 필요한가 |
|---|---|---|
| 1 | **IDLE → DONE 통주행** (성공 사례) | 정상 궤적의 기준선. 이게 없으면 "위반"의 대조군이 없습니다 |
| 2 | **파지 실패 → 재시도 → 성공** | 실패 복구 경로. 성공만 녹화하면 절반입니다 |
| 3 | **INSERT 성공** (여러 클래스) | I1·I2 검증의 근거 |
| 4 | **INSERT 차단(⛔) 분기** | 좌우 오프셋 게이팅이 실제로 도는 장면 — 지금 🟡 코드만 |
| 5 | **사선 진입** INSERT | 지금 🔴 미검증. 아래 P2-4 참고 |
| 6 | **워치독 발동** (Host 를 일부러 끊음) | I4 의 유일한 실측 기회 — 아래 P2-2 |
| 7 | **정지 명령 → 실제 정지** | I2 의 유일한 실측 기회 — 아래 P2-1 |
| 8 | 여섯 클래스 각각 1회 이상 | 클래스별 편차 |

> **시행마다 한 줄 메모를 남기세요.** bag 파일명만으로는 3개월 뒤에 무엇이었는지
> 모릅니다. `recordings/final/INDEX.md` 에 `bag 이름 · 무엇을 한 시행 · 결과 ·
> 특이사항` 네 칸으로 적으면 충분합니다.

# P2 — 하드웨어로만 잴 수 있는 값 (약 4시간)

**소프트웨어로 대체 불가능한 것만 골랐습니다.** 나머지는 나중에 맥에서 됩니다.

## P2-1. `T_stop` — 정지 지연과 오버슈트 🔴 최우선

**불변식 I2 의 전부입니다.** 지금 문서에 있는 235 ms 는 **계산값이지 실측이
아닙니다** (Host 125 + UDP 10 + Pi 100).

| 재는 것 | 방법 |
|---|---|
| stop 수신 시각 → 마지막 비영 `/cmd_vel` 시각 | bag 타임스탬프 차이 |
| 그동안 실제 이동 거리 | 바닥에 테이프로 표시 후 자로 실측 |

절차: 직진 0.1 m/s 로 보내다가 임의 시점에 stop → 정지 지점 표시 → 반복 5회.
**0.06 m/s 구간에서도 5회** (바구니 접근 속도).

> 이 값 하나가 RoboSec 리포트에서 **"오버슈트가 허용창(±15 mm)보다 큰가"** 라는
> 핵심 질문에 답합니다. 못 재면 그 질문을 못 씁니다.

## P2-2. 워치독 발동 시간과 그동안의 이동 🔴

**불변식 I4.** `HOST_COMMAND_TIMEOUT_CYCLES = 3` 인데, 제어 주기가 1.6 Hz 였을 때
이 "3사이클"이 0.3초가 아니라 1.8초였다는 것이 이미 확인된 사실입니다.
**9.6 Hz 로 고친 뒤의 실제 값을 아직 안 쟀습니다.**

절차: 직진 중 Host 를 끊는다 → bag 에서 마지막 명령 수신 시각과 안전 전이 시각의
차이 → 그동안 이동한 거리 실측. 5회 반복.

## P2-3. `identify_target` 왕복 지연 🔴

`BASELINE_MISSION_TODO.md` 에 **"클래스를 하나씩 물어보는 방식 — 왕복 6회의 실제
지연 미측정"** 으로 남아 있는 항목입니다.

절차: 여섯 클래스를 순서대로 물어보고 각 왕복 시간을 로그. 3회 반복.

## P2-4. 사선 진입 INSERT 🔴

`BASKET_LATERAL_TOLERANCE_M = 0.070` 이 **유일한 계산값**이고 실측이 없습니다.
차량이 바구니에 정면이 아니라 비스듬히 도달할 수 있으므로 실제 허용폭을 알아야
합니다.

절차: 15°, 30° 사선으로 접근해 INSERT 시도 → 성공/실패와 실제 좌우 오프셋 기록.
각도당 3회.

> ⚠️ **안전:** P2-1·P2-2 는 차량이 움직이는 실험입니다. 처음 1회는 **바퀴를
> 띄우고** 로그만 봅니다. 거리를 재야 하므로 이후에는 바닥에서 하되, 주변을
> 비우고 E-STOP 을 손에 두세요.

# 9월 8일 이후 — RoboSec 는 어떻게 되나

**없어지지 않습니다. 방법론이 바뀝니다.**

## 왜 계속 가능한가

RoboSec 가 검사하려는 대상 대부분이 **순수 파이썬이고 하드웨어를 모릅니다.**

| 대상 | 하드웨어 필요? |
|---|---|
| `domain/task/motion.py` — 속도 클램프, 제자리회전 검사 | ❌ 불필요 |
| `domain/task/baseline_mission.py` — FSM, 워치독 | ❌ 불필요 |
| `domain/adapters/real/udp_host_link.py` — 파서, 최신 우선 | ❌ 불필요 |
| `domain/task/preconditions.py` · `corrections.py` | ❌ 불필요 |
| **물리적 결과** (실제 이동 거리, 오버슈트) | ✅ 필요 → **녹화본으로 대체** |

**이건 우연이 아니라 설계의 배당금입니다.** grippers 를 Ports & Adapters 로
만들고 Fake 어댑터를 갖춘 덕에, 도메인 로직이 하드웨어 없이 그대로 돕니다.
CI 가 매 push 마다 Fake 어댑터로 전 미션 파이프라인을 도는 것과 같은 이유입니다.

## 바뀌는 것

| | 원래 계획 | 9/8 이후 |
|---|---|---|
| 실험 방식 | 실기에 명령 주입 | **도메인 코드 fuzzing + 녹화본 replay** |
| 검증 기준 | 로봇의 실제 거동 | **모델이 녹화된 궤적을 재현하는가** |
| 물리 상수 | 실험 중 측정 | **9/8 전에 확보한 값 고정** |
| E4(워치독) | 실기 | P2-2 실측 1회 + 나머지는 모델 |

## 이게 약한 방법론인가 — 아닙니다

**모델 기반 탐색 + 제한된 물리 검증**은 사이버-물리 시스템 보안 연구의 표준
구성입니다. 중요한 것은 두 가지입니다.

1. **모델이 실측과 얼마나 맞는지 보이는 것** — 녹화본이 그 근거입니다
2. **검증하지 못한 것을 정확히 밝히는 것** — Limitations 에 쓰면 됩니다

리포트에는 이렇게 적습니다:

> Physical validation was performed on N recorded runs before hardware access
> ended on 2026-09-08. Subsequent exploration is model-based, using the
> hardware-independent domain layer as the system under test, with recorded
> traces as ground truth.

**오히려 이 제약이 논지를 선명하게 만듭니다** — "소프트웨어가 보장하는 것"과
"물리가 실제로 하는 것"을 강제로 분리하게 되고, 그것이 I1~I8 을 나눈 이유
그 자체입니다.
