## #1 — STS3215 ros2_control 실기 MoveIt 〔가장 급함: 실기 데모가 9/8 전에만〕

이건 "캡처"가 아니라 **개발**이다. 실물 팔을 MoveIt 으로 움직이려면 Feetech
STS3215 시리얼 버스를 ros2_control `SystemInterface`(C++ 플러그인)로 감싸야 한다.

- **오프라인 선작업(지금 가능, HW 0)**: SystemInterface 플러그인 골격 작성.
  grippers `arm_driver` 의 시리얼 통신 코드를 재사용하면 지름길(read: 관절 위치,
  write: 목표 위치). 데스크탑에서 빌드까지 맞춰 둔다.
- **9/8 전 필수 캡처**: 실물 팔이 MoveIt 계획 궤적을 실행하는 영상 + `/joint_states` bag.
  - 최소 목표: 한 관절 read/write 왕복 확인 → 전 관절 → 한 개 계획 궤적 실행.
  - 폴백: 인터페이스가 완성 안 되면 read-only(관절 상태 스트림) + 단일 관절 명령
    영상이라도 확보.
- 리스크: 8일 안에 HW 디버깅. 선작업으로 HW 시간을 "작성"이 아니라 "디버깅"에만 쓴다.

## #2 — 분산 로봇 링크·타이밍 특성화 (Host↔Pi↔STM32) 〔캡처 가장 쌈〕

- **오프라인 선작업(지금 가능)**: 양단 타임스탬프 프로브 도구.
  - UDP: Host↔Pi 왕복 ping 프로브(각 끝에서 tx/rx 타임스탬프, seq 부여). 로컬
    루프백에서 도구 자체 검증.
  - 시리얼 기준선: Host↔Arduino Uno echo(로봇 밖 통제값). **검증됨 7.08ms**.
    실기 시리얼은 Pi↔**STM32**(echo 아님) — 기존 프로토콜 명령→응답을 계측.
- **9/8 전 필수 캡처**: 부하 스윕별 tx/rx 로그.
  - 부하 3단계: idle · 중간(perception 동작) · 고부하(perception+모터+주행).
  - UDP 왕복·단방향(오프셋 추정), Pi↔STM32 프로토콜 왕복. 각 1~2분.
- 이후(오프라인): 지연·지터·손실·재정렬·클럭드리프트 분석 + 분포 시각화.
- 시간: 로봇 ~1~2h.

## #3 — LiDAR–뎁스카메라 외부 캘리브레이션 & 융합 〔영상 포함 유일〕

- **9/8 전 필수 캡처**: 동기화된 `/scan`(LiDAR) + depth + RGB + `/tf` bag.
  - 평면 캘리브 타깃(체커보드/판)을 ~10 포즈(거리·각도)로. 로봇 정지, 타깃 이동
    또는 로봇을 포즈로 이동.
  - 11.3° 하향 틸트는 사전 prior 로 사용(메모리).
- 이후(오프라인): LiDAR 점군을 카메라 프레임에 투영해 외부 파라미터(R·t) 추정,
  융합·거리 교차검증, 투영 오버레이 시각화.
- 시간: 로봇 ~0.5~1h.

## #4 — 메카넘 오도메트리 정확도 & 슬립

- **9/8 전 필수 캡처**: 정해진 궤적 주행 bag — 휠 오도메트리 + LiDAR + `/cmd_vel`.
  - 궤적: 직진 N m · 제자리회전 360° · 대각 이동 · **닫힌 루프(출발점 복귀)**.
  - 데드밴드(0.05 m/s) 부근 저속 주행 1건 — "명령은 갔는데 안 움직이는" 구간 확보.
- 이후(오프라인): 오도메트리 적분 vs LiDAR/SLAM 지상진실, 드리프트·슬립 정량화.
- 시간: 로봇 ~1h.
