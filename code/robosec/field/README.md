# RoboSec 실기 자동화 — 사람 손을 최소로

2026-09-08 실기에서, **사람이 직접 해야 하는 건 03(주입) 한 단계뿐**이 되도록
앞뒤를 스크립트로 엮어 두었다. 나머지(01·02·04)는 맥/SSH 로 자동 실행된다.

## 안전 — 바퀴를 띄운다 (권장), 전원 스위치는 최후수단

이 로봇에는 빨간 버튼식 비상정지가 없다. 그리고 **메인 전원 스위치는 STM32 와
Pi 가 한 배터리를 공유해, 내리면 Pi 까지 같이 꺼진다** — 진행 중 세션·녹화가
날아가고 SD 카드 손상 위험도 있다. 그래서 이걸 상시 E-STOP 으로 삼지 않는다.

**대신 차량을 받침대(스탠드/상자)에 올려 바퀴를 공중에 띄운다.** F1·F2 관측은
"바퀴가 도는가"이므로 **바퀴를 띄워도 그대로 관측되고**, 로봇이 병진·충돌하지
않아 애초에 급정지가 거의 필요 없다. 이게 이 테스트의 1차 안전장치다.

- 녹화는 `/shared`(호스트 마운트)에 남겨 전원이 끊겨도 살아남게 했다(02 가 그렇게 함).
- 그래도 정말 세워야 하면 **메인 전원 스위치**가 최후수단이다(Pi 도 같이 꺼짐을 감수).
- 모터 전원만 따로 끊는 스위치는 이 보드 기본구성엔 없다 — 그런 인라인 스위치를
  모터 전원선에 달아 두면 "Pi 는 살리고 바퀴만 죽이는" E-STOP 이 되지만, 그건
  하드웨어 개조다. 배선을 아는 사람이 판단할 몫이다.

## 분담

| 단계 | 스크립트 | 누가 | 로봇이 움직이나 |
|---|---|---|---|
| 01 사전점검 | `01_preflight.sh` | 자동(제가) | ✗ |
| 02 기동+녹화 | `02_bringup_and_record.sh` | 자동(제가) | ✗ (IDLE 정지) |
| **03 주입** | `03_inject_guided.sh` | **사람** | **✔ 바퀴가 움직임** |
| 04 회수+분석 | `04_collect_and_analyze.sh` | 자동(제가) | ✗ |

**팔·그리퍼는 전 과정 안 움직인다** (`use_fake_arm:=true`, arm_driver 미기동).
움직이는 것은 바퀴뿐이고, 그것도 03 에서만.

## 실행 순서

```
bash field/01_preflight.sh          # 20/21 + Pi 도달 + baseline 확인
bash field/02_bringup_and_record.sh # 컨트롤러→orchestrator→녹화, 검증 3줄
# ── 여기서 사람이 등장 ──────────────────────────────
bash field/03_inject_guided.sh      # 빈 공간·전원스위치 손·Enter 로 하나씩
# ────────────────────────────────────────────────
bash field/04_collect_and_analyze.sh# 녹화 회수 → 불변식 스캔 → 20/21 대조
```

## 03 에서 사람이 하는 것 (그게 전부)

1. 차량을 **받침대에 올려 바퀴를 띄운다** (병진·충돌 원천 차단).
2. 만일에 대비해 **메인 전원 스위치를 손 닿는 곳에** 둔다 (최후수단 — Pi 도 같이 꺼짐).
3. 스크립트가 공격마다 멈춘다 — 안전하면 **Enter**, 정말 이상하면 **전원 내림**.
4. **a4(F1)의 마지막 nan 패킷**에서 바퀴가 *정지 / 마지막값 유지 / 폭주* 중
   무엇인지 눈으로 기록(녹화도 같이 남는다).

나머지 관측(위반 스캔·예측 대조·문서화)은 04 이후 제가 한다.

## 안전 원칙 (RUNBOOK §0 그대로)

- 바퀴는 띄워 둔다 — 급정지가 거의 필요 없게 만드는 게 최선.
- 멈출 때 **노드를 죽이지 않는다**(마지막 명령 latch). 정말 세워야 하면 메인 전원(Pi 도 꺼짐).
- **한 번에 한 공격**, 사이 30초, 다음 전 IDLE 복귀.
- attacker 가 5005 의 **유일한 발신자** — 맥에서 정상 Host 미션을 동시에 돌리지 않는다.
