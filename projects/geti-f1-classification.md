# Intel Geti — F1 차량 팀 분류

> **2026-08 · 단독 · Intel Physical AI 과정 MLOps 모듈 과제**
>
> **결과: 같은 데이터 400장으로 Detection 58% → Segmentation 91%.
> 데이터를 늘려서가 아니라 라벨 형태를 바꿔서 얻은 33%p 입니다.**

---

## 1. Problem

F1 중계를 보다 보면 차량이 너무 빠르게 지나가 **어느 팀 머신인지 눈으로 따라가기
어렵습니다.** 사람도 놓치는 걸 AI 가 잡아낼 수 있는가 — 여기서 시작했습니다.

**문제 설정이 까다롭습니다.** F1 은 규정상 머신 형상이 거의 동일해서
**리버리(도색) 색상이 사실상 유일한 단서**입니다. 형태로 구분할 수 없습니다.

| | |
|---|---|
| 클래스 | **7개 팀** — alpine · ferrari · haas · mclaren · mercedes · redbull · williams |
| 데이터 | **400장** (라벨당 50장) |
| 환경 | Intel Geti 웹 UI — **코드 한 줄 없음** |

---

## 2. Architecture — No-Code MLOps

```
데이터 수집 (중계 화면 400장)
      ↓
Intel Geti  ─ Annotation ─ Train ─ Active Learning ─ Test
      ↓                              ↑
   Active model                      └─ 애매한 샘플 우선 라벨링
      ↓
OpenVINO 배포 (model.xml + model.bin)
```

**Geti 를 쓴 이유**는 도구 없이 학습할 때 생기는 문제 — 어노테이션 관리, 재현,
버전, 재학습 트리거가 전부 수작업 — 를 피하기 위해서입니다.

## 4. Design Decisions

### 같은 데이터로 두 태스크를 모두 해봤다

**이것이 이 프로젝트의 핵심 선택입니다.** 처음에는 Detection 만 할 계획이었지만
58% 에 그쳤습니다. 그때 **"데이터가 부족한가, 라벨이 문제인가"** 를 가르기 위해
**동일한 400장을 그대로 재라벨링**했습니다.

변수를 하나만 바꾼 것이 결론을 명확하게 만들었습니다.

### Detection 에 회전 바운딩 박스를 썼다

F1 머신은 코너링·측면 샷에서 기울어져 있어, 축 정렬 사각형은 배경을 과도하게
포함합니다. **Rotated Bounding Box** 를 썼는데도 부족했습니다.

### 클래스 균형을 맞췄다

**라벨당 50장** 기준을 유지해 클래스 불균형을 막았습니다.

---

## 5. Implementation

- **Intel Geti** 웹 UI — Project Creation → Task Selection → Annotation →
  Train → Test
- Detection: **Rotated Bounding Box Tool** — 겹침·부분 가림 차량도 보이는 만큼
- Segmentation: **Polygon Tool** — 프론트윙·리어윙·타이어의 복잡한 실루엣까지
  따라 그리고 배경(트랙·잔디)은 완전히 배제

---

## 6. Problems & Debugging

### 가설이 틀렸다 — 데이터가 아니라 라벨이 문제였다

```
Symptom      Detection 최고 정확도가 58% 에서 안 오름
Hypothesis   400장은 너무 적다 (데이터 부족)
Experiment   같은 400장을 폴리곤으로 재라벨링 — 데이터는 그대로, 라벨만 변경
Result       91%  (+33%p)
Root Cause   회전 구도에서 사각형 박스가 트랙·잔디·펜스를 대량 포함했다
             박스가 겹치면 뒤 차량이 억제되어 아예 미검출
```

> **데이터를 더 모으는 쪽으로 갔으면 시간만 쓰고 못 고쳤을 문제입니다.**
> 변수를 하나만 바꿔 확인한 것이 답을 냈습니다.

### 레드불만 유독 안 잡혔다

다른 팀은 90%대인데 레드불만 81% 또는 미검출이었습니다.

**원인은 모델이 아니라 데이터의 성질입니다** — F1 은 경기마다 래핑(도색)이
바뀝니다. 스페셜 리버리 · 스폰서 교체 · 시즌 중 업데이트. **같은 팀인데 색이
다릅니다.** 레드불이 그 변화가 가장 심합니다.

색이 유일한 단서인 문제에서, 그 단서 자체가 흔들린 것입니다.

---

## 7. Verification

실제 중계 사진으로 라이브 예측을 돌려 확인했습니다.

```
메르세데스 98~99%   (고속 블러에도 성공)
페라리     91~97%
맥라렌     98%
레드불     81% 또는 검출 실패   ← 유일한 실패
```

## 8. Results

| 태스크 | 라벨 방식 | 모델 | 정확도 |
|---|---|---|---|
| **Detection** | Rotated BBox | MaskRCNN-ResNet50-V2 | **58%** |
| | | MaskRCNN-EfficientNetB2B (Speed) | 26% |
| **Segmentation** | Polygon Mask | MaskRCNN-ResNet50-V2 (Balance) | **91%** |
| | | MaskRCNN-EfficientNetB2B | 22% |
| | | MaskRCNN-Swin-T (Accuracy) | 2% — **학습 실패** |

### 두 방식의 비교

| | Detection (사각형) | Segmentation (폴리곤) |
|---|---|---|
| 배경 포함 | 회전 구도에서 **대량** | 픽셀 단위라 거의 없음 |
| 겹친 차량 | 뒤 차량 **억제·미검출** | **각각 분리 검출 성공** |
| 라벨링 비용 | 빠름 (클릭 2회) | **3~4배** |

**라벨링에 3~4배를 더 쓰고 33%p 를 얻었습니다.** 이 교환이 이 문제에서는
명백히 이득이었습니다.

---

## 9. Limitations

- 🔴 **데이터셋 일관성** — 경기마다 바뀌는 래핑 때문에 같은 클래스 안의 색이
  일정하지 않습니다. 레드불 실패의 직접 원인이며, **데이터를 더 모아도 이 문제는
  안 없어집니다**
- 🔴 **400장은 여전히 적습니다** — Segmentation 91% 도 절대 기준으로 높지 않고,
  Swin-T 는 아예 학습에 실패했습니다
- 🟡 **No-Code 의 한계** — 모델 내부를 못 봅니다. Swin-T 가 왜 2% 인지
  진단할 수단이 UI 안에 없었습니다
- 🟡 실제 중계 영상(연속 프레임)이 아니라 **정지 이미지**로만 평가했습니다
