# Desktop Benchmark Dashboard — Streamlit 데이터 분석 대시보드

> *2026-09 · 단독 · 데스크탑(Intel Arc B580) 데이터 분석 트랙*
>
> [A1](a1-edge-opt.md) · [Edge Perception Desktop](edge-perception-desktop.md) ·
> [ACT vs SmolVLA](act-vs-smolvla-offline.md) 세 프로젝트에서 나온 실측치를 **새로
> 측정하지 않고** 하나의 인터랙티브 대시보드로 묶었다. 이 데스크탑을 데이터 분석
> 관점에서 다룬 첫 프로젝트다.

---

## Problem

세 프로젝트의 결과가 각자 마크다운 표로 흩어져 있었다 — 디바이스별 fps, 클래스별
mAP50, 두 정책의 loss curve. 표로는 "INT8이 어느 하드웨어에서 반례인가", "재샘플링이
어느 클래스를 얼마나 살렸는가" 같은 **여러 축을 한눈에 비교하기 어렵다.** 이미 있는
숫자를 다시 재는 대신, **보는 방식을 데이터 분석 도구로 바꿔** 같은 결론이 더 잘
드러나는지 확인한다.

## Method

- 세 프로젝트의 `code/*/metrics.json`·`a1_bench_results.md`·`act_vs_smolvla_latency.json`에서
  실측치를 `data.json` 하나로 옮겨 담았다(계산은 하지 않고 그대로 복사 — 원본과 대조
  가능하도록 출처를 코드 섹션에 명시).
- Streamlit + Plotly로 탭 3개짜리 대시보드 구성: 엣지 AI 추론(A1) · 자율주행
  인지모델(BDD100K) · 로보틱스 정책 비교(ACT vs SmolVLA).
- 이 데스크탑(Arc B580) 자체에 배포해 `0.0.0.0:8501`로 띄우고, Tailscale 네트워크로
  접속 확인.

## Results

| 항목 | 값 |
|---|---|
| 실행 위치 | `intel-B860M-DS3H` (Tailscale IP, 포트 8501) |
| 접속 확인 | `curl` HTTP 200 (Tailscale 네트워크 내부에서) |
| 데이터 소스 | 3개 프로젝트, 재측정 없이 실측치만 재구성 |
| 시각화 | 막대(디바이스별 fps·INT8 배속), 로그축 막대(클래스별 인스턴스 수), 라인(loss curve), 메트릭 카드 |

대시보드가 드러내는 것 — 표에서는 놓치기 쉬웠던 것들:
1. **INT8 배속 그래프에서 1.0 기준선을 그으면 반례(NPU·맥 CPU)가 즉시 눈에 띈다** —
   표로는 "어느 게 1보다 작은가"를 매번 계산해서 읽어야 했다.
2. **클래스별 인스턴스 수(로그축)와 mAP50을 나란히 두면, "왜 이 클래스만 0인가"의
   답이 그래프 두 개를 겹쳐 보는 것만으로 드러난다** — rider·bicycle·motorcycle·train의
   막대가 나머지보다 몇 자릿수 낮다.
3. **loss curve를 겹쳐 그리면 "절대값 비교 불가"라는 문서의 경고가 시각적으로도
   바로 확인된다** — 두 곡선의 시작점·기울기가 애초에 다른 척도임을 한눈에 보여준다.

## Findings

1. **재시각화만으로 새로운 사실이 나오진 않는다** — 이 대시보드는 세 문서의 결론을
   재확인·재전달할 뿐, 원본에 없던 통찰을 만들지는 않았다. 데이터 분석 도구의
   가치는 여기서는 "발견"이 아니라 **"전달"**에 있었다.
2. **하나의 스키마(`data.json`)로 세 프로젝트를 묶으니 상호 참조가 쉬워졌다** — 예를
   들어 A1의 "NPU가 INT8에서 느려진다"와 정책 비교의 "SmolVLA 경량화가 실패했다"를
   나란히 보면, **이 데스크탑에서 양자화가 항상 이득은 아니라는 패턴**이 프로젝트
   경계를 넘어 반복됨을 알 수 있다 — 개별 문서에서는 안 보이던 결이다.
3. Streamlit을 이 데스크탑에 직접 배포해 Tailscale로 접속하는 구성 자체가, "이
   데스크탑을 데이터 분석 서버로도 쓸 수 있다"는 걸 보여준다 — 로컬 개발 후
   원격으로 결과만 보내는 방식이 아니라, 대시보드 자체가 이 하드웨어에서 돈다.

## 정직한 한계

- **이 대시보드는 새 데이터를 만들지 않는다.** 세 프로젝트에서 이미 확정된 수치를
  그대로 옮겼을 뿐이며, 옮기는 과정에서의 오탈자 위험은 있다 — 표시된 숫자가
  의심되면 항상 원본 문서(`a1-edge-opt.md` 등)를 우선한다.
- **인증·HTTPS가 없다.** Tailscale 네트워크 내부에서만 접근 가능하다는 것을 유일한
  접근 통제로 두고 있다 — 공개 인터넷에 노출하려면 별도 조치가 필요하다.
- 세 프로젝트 중 하나(예: A2, udp-network-lab)라도 갱신되면 `data.json`을 수동으로
  다시 옮겨야 한다 — 자동 동기화는 하지 않았다.

## Future Work

- `data.json`을 수동 복사 대신 각 프로젝트의 `metrics.json`을 직접 읽어오도록 바꿔
  "갱신하면 자동 반영"되게 만들기.
- A2(합성-실사 갭)·udp-network-lab(퍼징 결과)도 탭으로 추가해 전체 데스크탑 실험을
  한 대시보드에 모으기.
- 접근 통제(간단한 인증)를 추가해 공개 네트워크에서도 안전하게 열람 가능하게.
